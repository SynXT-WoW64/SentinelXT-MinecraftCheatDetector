# SentinelXT changelog

## Product version 0.1.4 · Build #6

- Поиск X-Ray по названию стал нечётким: учитываются регистр, разделители, цифры, невидимые символы, похожие кириллические/греческие буквы, leet (`xr4y`), перестановки и одиночные опечатки (`xrya`, `xrray`, `x.r.a.y`). Имена сетевого ПО (Xray VPN, Xray-core, V2Ray) по-прежнему исключены.
- Причина «X-Ray не найден» устранена: имя `xray` раньше намеренно не попадало в совпадения по файлам, а ZIP вне игровых папок вообще не проверялись. Новый модуль `scanners/trace_scanner.py` проходит по пользовательским папкам, Temp, AppData и всем локальным дискам независимо от расположения файла.
- Ресурс-пак находится по содержимому даже под нейтральным именем (`holiday.zip`) и даже с чужим расширением (`.dat`, `.bin`, `.tmp` и т. п. при ZIP-сигнатуре).
- Новые источники следов: Корзина (исходные имя, путь и время удаления из записей `$I`), недавние файлы Windows (Recent) и Prefetch (запуски программ; нужны права администратора).
- Вкладка «Результаты»: группы по темам, компактные строки «файл — тип / папка / время», поиск по пути и доказательствам, скрытие информационных записей (разрешённые моды, лаунчеры) по умолчанию, кнопка «Копировать список».
- Минимальный размер ZIP для структурной проверки снижен до 300 байт: X-Ray-паки бывают очень маленькими.
- Тесты: нечёткие имена, Корзина v1/v2, Recent, Prefetch, переименованные и замаскированные паки, группировка результатов.

## Product version 0.1.4 · Build #5

- Новый модуль `scanners/name_matcher.py`: устойчивое сопоставление имён X-Ray/ore finder/cave finder независимо от регистра, разделителей, суффиксов и цифр (`xray`, `x-ray`, `x_ray`, `X Ray`, `xray123`, `xr4y`) и кириллических двойников (например, `х` вместо `x`).
- Имена сетевого ПО (Xray VPN, Xray-core, V2Ray, 3x-ui и подобные) не считаются совпадением X-Ray при поиске по именам файлов. Для файлов, структура которых уже подтверждена как ресурс-пак Minecraft, имя остаётся слабой зацепкой.
- Анализ ресурс-паков теперь проверяет не только прозрачность текстур, но и пустые модели базовых блоков (`models/block/*.json` с пустым `elements`): блоки не рисуются. Новая запись «X-Ray-подобные модели блоков» во вкладке «Результаты».
- Расширен список проверяемых блоков и руд: deepslate-руды, незер-руды, древние обломки, cobblestone, gravel, sand и др.
- Лимит приоритетно проверяемых ZIP-паков вне `.minecraft` повышен с 6 до 25; раньше ZIP-паки сверх шести пропускались.
- Определение ZIP как ресурс-пака учитывает больше текстур, включая `deepslate.png` и `cobblestone.png`.
- Добавлены тесты: варианты имён, исключения сетевого ПО, пустые модели, отсутствие ложных срабатываний.

## Product version 0.1.4 · Build #3

- WI Zoom больше не классифицируется как Wurst Client только из-за встроенного namespace/API-reference. Allow-list имеет приоритет при отсутствии точного запрещённого ID/метаданных; namespace остаётся видимым в записи доказательств.
- Улучшена нормализация идентификаторов и Unicode-confusables. Изменение регистра, разделителей и добавление суффикса к имени не удаляет совпадение из списка ручной проверки.
- Поиск внешних resourcepacks выполняется раньше длительного общего обхода и приоритетно проверяет каталоги `resourcepacks` на вторичных локальных дисках.
- Поддержаны legacy ZIP-паки без `pack.mcmeta`, включая текстуры `textures/blocks`.
- X-Ray определяется по набору текстур обычных блоков и руд; название архива используется только для приоритета поиска.
- Удалены risk/confidence/evidence-strength/score поля. Результаты показывают обнаруженные факты без числового ранжирования.
- Обновлены тесты на WI Zoom, изменённые названия чит-клиентов, старые X-Ray ZIP и отсутствие оценок риска.

## Product version 0.1.4 · Build #1

- Добавлены ограниченные по времени инвентаризация игровых каталогов и анализ архивов.
- Добавлен локальный реестр политики RUStrengthSMP и анализ лаунчеров, модов, скриптов, PE и JVM-конфигураций.
