## О проекте

**SentinelXT** — настольный инструмент для администраторов Minecraft-серверов. Он помогает находить локальные следы лаунчеров, игровых установок, модификаций, чит-клиентов и подозрительных ресурс-паков, а затем показывает обнаруженные признаки и доказательства для ручной проверки.

Проект использует локальный реестр правил **RUStrengthSMP**. Это политика конкретного сервера, а не универсальный список запрещённых Minecraft-модификаций.

## Возможности

- **Инвентаризация Minecraft:** поиск известных лаунчеров, игровых каталогов, установок, папок модов, версий, ресурс-паков и шейдеров.
- **Анализ JAR/ZIP/MRPack:** чтение метаданных модов, идентификаторов, имён пакетов и строк классов без запуска содержимого.
- **Анализ EXE/DLL:** статическое чтение PE-метаданных, импортов и строковых маркеров. Одного имени файла недостаточно для идентификации.
- **Проверка конфигураций и скриптов:** поиск подозрительных JVM/Java Agent параметров и маркеров в скриптах автоматизации.
- **X-Ray-анализ ресурс-паков:** проверка прозрачности текстур обычных блоков и руд, пустых моделей блоков, а также архивов, замаскированных под другие расширения.
- **Поиск следов:** проверка имён файлов и каталогов в доступных пользовательских местах, сведений Корзины, ярлыков Recent и записей Prefetch.
- **Гибкое сопоставление названий:** учёт регистра, разделителей, Unicode-похожих символов, leet-написания и небольших опечаток; известное сетевое ПО вроде Xray VPN не считается читом только по имени.
- **YARA и SHA-256:** локальные YARA-правила и база точных SHA-256 совпадений с проверкой только записей `verified: true`.
- **Результаты и отчёты:** группировка по категориям, фильтры, поиск по пути и доказательствам, копирование списка и локальные JSON-отчёты.
- **Дополнительный поиск через Everything:** при наличии установленного Everything и доступной `ES.exe` используется его индекс как дополнительный источник.
- **Интерфейс на трёх языках:** English, Русский и Українська.

## Совместимость

Основная целевая среда проекта:

| Компонент | Версия |
|---|---|
| ОС | Windows 7 SP1 x64 |
| Python | 3.8.10, 64-bit |
| GUI | PySide2 5.15.2.1 |
| Сборка EXE | PyInstaller 5.13.2 |

Зависимости зафиксированы в [`requirements-win7.txt`](requirements-win7.txt). Для работы с PE-файлами, изображениями и YARA используются `pefile`, Pillow и `yara-python` соответственно. Поведение отдельных анализаторов зависит от доступности этих библиотек и прав доступа Windows.

## Установка и запуск из исходников

1. Установите **Python 3.8.10 x64** и убедитесь, что команда `python` доступна в командной строке.
2. Распакуйте репозиторий и откройте его папку.
3. Установите зависимости:

   ```bat
   python -m pip install -r requirements-win7.txt
   ```

4. Проверьте окружение и локальные YARA-правила:

   ```bat
   python check_environment.py
   ```

5. Запустите приложение:

   ```bat
   python main.py
   ```

На Windows также можно использовать `install_dependencies.bat`, `check_environment.bat` и `run.bat`.

## Сборка EXE

После установки зависимостей запустите один из скриптов:

- `build_onefile.bat` — сборка одного EXE. Результат: `dist\SentinelXT-build6.exe`.
- `build_onedir.bat` — сборка приложения вместе с необходимыми файлами. Результат: `dist\SentinelXT\`.

PyInstaller создаёт каталоги `build/` и `dist/`, а также служебный `.spec`-файл. Эти артефакты не хранятся в исходном репозитории.

## Тесты

Запуск тестов:

```bat
python -m unittest discover -s tests -v
```

`test_ui_smoke.py` автоматически пропускается, если PySide2 не установлен. Для полной проверки интерфейса запускайте тесты в целевом Windows-окружении.

## Где хранятся отчёты

Отчёты сохраняются локально в JSON:

```text
%APPDATA%\SentinelXT\reports\
```

Приложение не отправляет результаты сканирования на сервер и не загружает найденные файлы в сеть.

## Важные ограничения

SentinelXT — инструмент статической инвентаризации и поиска индикаторов, а не доказательство нарушения правил.

- Найденное имя, строка, namespace или отдельная YARA-сигнатура могут относиться к разрешённому моду, совместимости или легальному инструменту.
- Наличие файла или исторической записи не доказывает, что файл запускался либо использовался во время игры.
- Запись Prefetch может указывать на запуск программы с соответствующим именем, но не подтверждает содержимое файла.
- Проверка ограничена временем, количеством файлов, размером архивов и доступными правами. Частичный отчёт не означает, что система чиста.
- Неизвестные, обфусцированные или загружаемые из сети модификации могут не иметь распознаваемых признаков.
- Утилита не исследует память процессов, удалённые данные или сетевой трафик.

**Любое совпадение требует ручной проверки.** Не используйте один результат SentinelXT как единственное основание для наказания игрока.

## Структура проекта

```text
SentinelXT/
├── assets/          # Иконка и логотип
├── core/            # Версия, локализация, пути и отчёты
├── database/        # Реестр политики, SHA-256 и YARA-правила
├── integrations/    # Дополнительная интеграция Everything
├── interface/       # PySide2-интерфейс и модель результатов
├── scanners/        # Инвентаризация и статические анализаторы
├── tests/           # Автоматические тесты
├── main.py          # Точка входа
└── requirements-win7.txt
```

## Политика RUStrengthSMP

Реестр сервера находится в [`database/policy_registry.json`](database/policy_registry.json). Перед использованием на другом сервере проверьте и адаптируйте этот файл под собственные правила. Разрешённые моды, серая зона и запрещённые идентификаторы зависят от политики конкретного сообщества.
